10) POST /api/logging/safe-text  (body contains \r\n, a fake ERROR line, and a Unicode line separator)
---------------------------------------------------------------------------------------------------------
Request body:
  {"text":"hello\r\nERROR forged log line\tafter tab"}

Response:
  {"example":"safe-text","requestId":"6a25fada-31c9-450c-a215-e1b3155f1e0d"}

Console:
  21:26:44.553 INFO  [http-nio-8083-exec-9] c.g.s.examples.SafeLoggingExamples requestId=6a25fada-31c9-450c-a215-e1b3155f1e0d   - User supplied note=hello__ERROR forged log line_after tab
  21:26:44.554 INFO  [http-nio-8083-exec-9] c.g.s.web.RequestLoggingFilter requestId=6a25fada-31c9-450c-a215-e1b3155f1e0d  event="http.completed" method="POST" route="/api/logging/safe-text" status="200" elapsedMs="6" - HTTP request completed

  Note: this is the log-injection demo. Even though the input contains
  \r\n and a tab, oneLine() replaces every control character with "_"
  before logging, so "ERROR forged log line" stays embedded inside the
  note=... value on a single real log line - it can never masquerade as
  its own ERROR-level entry. Compare to LoggingExamples.parameterized():
  placeholders alone (log.info("...{}", text)) do NOT do this sanitizing -
  oneLine() is what prevents the forged line.


11) POST /api/logging/async/1
------------------------------
Response:
  {"jobId":1,"requestId":"7a022a33-a38b-40f8-8ce9-d3fa24115935","threadName":"logging-demo-1"}

Console:
  21:26:44.595 INFO  [logging-demo-1] c.g.s.async.AsyncLoggingExamples requestId=7a022a33-a38b-40f8-8ce9-d3fa24115935  event="job.completed" jobId="1" - Worker processed demo job
  21:26:44.596 INFO  [http-nio-8083-exec-1] c.g.s.web.RequestLoggingFilter requestId=7a022a33-a38b-40f8-8ce9-d3fa24115935  event="http.completed" method="POST" route="/api/logging/async/{jobId}" status="200" elapsedMs="6" - HTTP request completed

  Note: the first line runs on thread "logging-demo-1" (the @Async worker
  pool, see AsyncConfig), not "http-nio-8083-exec-1" (the servlet thread
  that logs the second line) - yet both lines carry the SAME requestId.
  That's MdcTaskDecorator: it copies the calling thread's MDC onto the
  worker thread and restores the worker's own MDC afterwards, so the pool
  thread is safe to reuse for the next unrelated job.


12) Same /structured/1 call, but with --spring.profiles.active=json
---------------------------------------------------------------------
With the "json" profile (application-json.yaml: logging.structured.format.console=logstash),
the exact same log.atInfo().addKeyValue(...) call in LoggingExamples.structured() renders as
one JSON object per line instead of the %kvp text pattern shown in section 4:

  {"@timestamp":"2026-09-22T21:28:26.328395+03:00","@version":"1","message":"Order preview generated","logger_name":"com.gucardev.slf4jlogging.examples.LoggingExamples","thread_name":"http-nio-8084-exec-1","level":"INFO","level_value":20000,"requestId":"a7d66ed1-f23b-40bc-af1c-45fe03247969","event":"order.previewed","orderId":1,"itemCount":3}
  {"@timestamp":"2026-09-22T21:28:26.3646417+03:00","@version":"1","message":"HTTP request completed","logger_name":"com.gucardev.slf4jlogging.web.RequestLoggingFilter","thread_name":"http-nio-8084-exec-1","level":"INFO","level_value":20000,"requestId":"a7d66ed1-f23b-40bc-af1c-45fe03247969","event":"http.completed","method":"POST","route":"/api/logging/structured/{orderId}","status":200,"elapsedMs":93}

  Note: no code changes between text and JSON output - only the active
  Spring profile changes. addKeyValue("orderId", orderId) becomes a real
  JSON field "orderId":1 (numeric), not a quoted string.
