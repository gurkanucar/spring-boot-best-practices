# Spring Boot SLF4J Logging Example Project

A teaching catalog for `@Slf4j` / SLF4J 2 logging in Spring Boot: log levels,
parameterized and lazy logging, structured key/value logging, per-request
correlation via MDC (including across `@Async` worker threads), safe logging
of user input, JSON output, and file output with rolling.

Spring Boot 4.1.1 · Java 25

## Running

```bash
cd slf4j-logging
./mvnw spring-boot:run
```

The app starts on port `8083`. Every endpoint below is a `POST` and returns a
small acknowledgement JSON body containing the `requestId` that was attached
to its log lines.

```bash
curl -X POST http://localhost:8083/api/logging/levels/1
```

Real output for every endpoint (HTTP response + the exact console log lines
it produced) is captured in [`sample-output.txt`](sample-output.txt) — it was
generated by actually running the app and calling each endpoint with curl, not
hand-written.

## Endpoint catalog

| Endpoint | Technique demonstrated |
|---|---|
| `POST /api/logging/levels/{orderId}` | All five levels (`trace`/`debug`/`info`/`warn`/`error`) on one call |
| `POST /api/logging/parameterized/{orderId}` | `{}` placeholders instead of string concatenation |
| `POST /api/logging/lazy/{orderId}` | `isDebugEnabled()` guard vs. the fluent `atDebug()` API — neither computes the expensive summary when DEBUG is disabled |
| `POST /api/logging/structured/{orderId}` | Fluent `atInfo().addKeyValue(...)` structured logging |
| `POST /api/logging/audit/{orderId}` | A dedicated logger topic (`@Slf4j(topic = "audit")`) plus a `Marker` |
| `POST /api/logging/orders/{orderId}?mode=SUCCESS\|FALLBACK\|FAILURE` | Recoverable failure → `WARN` with context; unexpected failure → thrown and logged once, centrally |
| `POST /api/logging/sensitive` | A DTO whose `toString()` is redacted; only a masked email ever reaches the logger |
| `POST /api/logging/safe-text` | Log-injection defense: control characters and line separators in user input are neutralized before logging |
| `POST /api/logging/async/{jobId}` | `MDC` propagated from the HTTP thread into an `@Async` worker thread and cleaned up afterwards |

## Logging technique cheat sheet

The actual `log.*` calls behind each endpoint, exactly as written in the
source (see the file after each block).

**Levels** — five independent severities, filtered by the configured level:

```java
log.trace("Example TRACE: inspecting calculation steps orderId={}", orderId);
log.debug("Example DEBUG: preparing order orderId={}", orderId);
log.info("Example INFO: order accepted orderId={}", orderId);
log.warn("Example WARN: simulated slow dependency orderId={}", orderId);
log.error("Example ERROR: simulated processing failure orderId={}", orderId);
```
*(`LoggingExamples.levels`)*

**Parameterized (`{}` placeholders)** — no string concatenation, and the
arguments aren't even turned into a `String` unless the level is enabled:

```java
log.info("Order selected orderId={} itemCount={}", orderId, 3);
```
*(`LoggingExamples.parameterized`)*

**Guarded lazy evaluation** — the classic `isDebugEnabled()` check, needed
because plain Java method arguments (`expensiveSummary.get()`) are evaluated
before the call, regardless of whether DEBUG is enabled:

```java
if (log.isDebugEnabled()) {
    log.debug("Guarded summary orderId={} summary={}", orderId, expensiveSummary.get());
}
```
*(`LoggingExamples.lazy`)*

**Fluent lazy evaluation (SLF4J 2)** — `atDebug()` defers both formatting
*and* argument evaluation until `.log(...)` runs, and only if DEBUG is
enabled — so passing a `Supplier` here needs no manual guard:

```java
log.atDebug().addArgument(orderId).addArgument(expensiveSummary)
        .log("Lazy summary orderId={} summary={}");
```
*(`LoggingExamples.lazy`)*

**Structured / fluent key-value pairs** — typed fields (`orderId` stays a
`long`, not a formatted string) that show up as real fields in JSON output:

```java
log.atInfo()
        .addKeyValue("event", "order.previewed")
        .addKeyValue("orderId", orderId)
        .addKeyValue("itemCount", 3)
        .log("Order preview generated");
```
*(`LoggingExamples.structured`)*

**Marker + dedicated logger topic** — `@Slf4j(topic = "audit")` names the
logger `"audit"` instead of the class name, and `addMarker(...)` tags the
event for marker-based filtering/routing — both are independent of level:

```java
@Slf4j(topic = "audit")
public class AuditExamples {
    private static final Marker AUDIT = MarkerFactory.getMarker("AUDIT");

    public void orderProcessed(long orderId) {
        log.atInfo().addMarker(AUDIT)
                .addKeyValue("event", "order.processed.audit")
                .addKeyValue("actor", "demo-user")
                .addKeyValue("orderId", orderId)
                .log("Demo audit event");
    }
}
```
*(`AuditExamples`)*

**`WARN` for an expected, recoverable failure** — actionable context, no
stack trace, because the caller already handled it:

```java
try {
    throw new IOException("Simulated recommendation timeout");
} catch (IOException ex) {
    log.warn("Recommendations unavailable; using defaults orderId={}", orderId);
}
```
*(`OrderExamples.process`)*

**`ERROR` with a `Throwable` (throwable last)** — logged exactly once,
centrally, where the exception is actually handled, not where it was thrown:

```java
log.error("Order processing failed; see requestId for related events", ex);
// fluent equivalent: log.atError().setCause(ex).log("Order processing failed");
```
*(`LoggingExceptionHandler.handleProcessingFailure`)*

## Method reference and direct usage

Each technique also lives in a plain injectable `@Service`, independent of
the HTTP layer — inject it and call the method directly, e.g. from another
service, a scheduled job, or a message listener.

### `LoggingExamples`

```java
@RequiredArgsConstructor
class SomeCaller {
    private final LoggingExamples examples;

    void run(long orderId) {
        examples.levels(orderId);
        // trace/debug/info/warn/error, one call each, same orderId

        examples.parameterized(orderId);
        // log.info("Order selected orderId={} itemCount={}", orderId, 3);
        // placeholders, no string concatenation

        examples.lazy(orderId, () -> buildExpensiveSummary(orderId));
        // Supplier<String> — only invoked if DEBUG is enabled

        examples.structured(orderId);
        // log.atInfo().addKeyValue("orderId", orderId)... — fluent, typed key/value pairs
    }
}
```

`lazy(long orderId, Supplier<String> expensiveSummary)` is the one method
where the second argument matters: pass a `Supplier`, not an already-computed
`String` — `examples.lazy(orderId, expensiveSummary.get())` would defeat the
whole point by computing it unconditionally before the call.

### `AuditExamples`

```java
auditExamples.orderProcessed(orderId);
// logs on the "audit" logger (not the class logger) with an AUDIT marker
```

Takes no callback or extra data by design — it's a fixed-shape audit event.
To log a different audit fact, add a sibling method rather than a
generic `audit(String event, Object... kv)`, so each audit event stays
independently greppable and typed.

### `OrderExamples`

```java
OrderExamples.Result result = orderExamples.process(orderId, OrderExamples.Mode.SUCCESS);
// result.orderId(), result.status() — status is "primary" or "fallback"

orderExamples.process(orderId, OrderExamples.Mode.FALLBACK);
// internally catches an IOException and logs WARN with context, no stack trace

orderExamples.process(orderId, OrderExamples.Mode.FAILURE);
// throws IllegalStateException — deliberately NOT caught here; let it
// propagate to LoggingExceptionHandler, which is the only place that logs it
```

Never wrap a call to `process(..., Mode.FAILURE)` in a local
try/catch that also logs — that would double-log the same failure. Let it
propagate.

### `SafeLoggingExamples`

```java
safeLoggingExamples.loginAttempt(email);
// logs event="login.demo" + emailMasked="***@domain" — never the raw email or any credential

safeLoggingExamples.userSuppliedText(freeformNote);
// logs "User supplied note={}" with control chars/line separators replaced by "_"

String masked = SafeLoggingExamples.maskEmail(email);   // static, e.g. "***@example.com"
String safe   = SafeLoggingExamples.oneLine(freeformNote); // static, single-line, max 120 chars
```

`maskEmail` and `oneLine` are `static` on purpose — they're pure string
transforms with no dependency on the logger, so reuse them anywhere you're
about to log user-controlled text, not just inside this class.

### `AsyncLoggingExamples`

```java
CompletableFuture<AsyncLoggingExamples.Result> future = asyncLoggingExamples.run(jobId);
AsyncLoggingExamples.Result result = future.join();
// result.jobId(), result.requestId() (copied from the caller's MDC), result.threadName()
```

Must be called through the injected Spring-managed bean (as in
`LoggingController.async(...)`), never as `new AsyncLoggingExamples().run(...)`
or via a private/same-class call — `@Async` only takes effect through the
Spring AOP proxy.

### `MdcTaskDecorator`

```java
ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
executor.setTaskDecorator(new MdcTaskDecorator());
// wrap any Runnable submitted to this executor; MDC.getCopyOfContextMap()
// at submission time travels with it, and the worker's own prior MDC is
// restored afterward — safe to reuse across unrelated tasks
```

Not meant to be called directly (`decorate(task).run()`); it's a
`TaskDecorator` — set it on an executor once (see `AsyncConfig`) and every
task submitted to that executor gets MDC propagation for free.

## Levels and profiles

`application.yaml` sets `com.gucardev.slf4jlogging` to `INFO` by default, so
`log.trace(...)` and `log.debug(...)` are no-ops unless a profile raises it.
`application-dev.yaml` raises it to `TRACE` — run with
`--spring.profiles.active=dev` to see every level from `/levels/{orderId}`.

## Correlation: MDC and requestId

`RequestLoggingFilter` puts a `requestId` (from `X-Request-ID` if it looks
safe, otherwise a fresh UUID) into MDC before the request is handled, echoes
it back as a response header, and always restores the servlet thread's prior
MDC state in a `finally` block — servlet threads are pooled and reused, so a
leaked value would bleed into the next unrelated request.

`MdcTaskDecorator` does the equivalent for `@Async`: it captures the calling
thread's MDC at submission time, installs it on the worker thread, and
restores the worker's own prior context afterward. `/async/{jobId}` proves
this — its first log line runs on thread `logging-demo-1` and its second runs
on an `http-nio-...` thread, but both carry the same `requestId`
(`sample-output.txt`, section 11).

## Structured logging: text vs. JSON

The same code — `log.atInfo().addKeyValue("orderId", orderId)...` — renders
differently depending on the active profile:

- Default profile: the `%kvp` conversion in `application.yaml`'s console
  pattern renders key/value pairs as `orderId="1"` text after the message.
- `--spring.profiles.active=json` (`application-json.yaml`): the exact same
  call becomes one JSON object per line, with `orderId` as a real numeric
  field. See `sample-output.txt`, section 12, for a real captured line of
  each.

No source code changes between the two — only `logging.structured.format`.

## File output and log rotation

`--spring.profiles.active=file` (`application-file.yaml`) writes the same
structured JSON lines to `logs/slf4j-logging.log`, rolled daily or at 10MB,
gzip-compressed, capped at 7 files / 100MB total, with old files cleaned on
startup.

## Async appender (optional)

`--spring.profiles.active=async-log` swaps in `logback-async-spring.xml`,
which wraps the console appender in Logback's own `AsyncAppender` (a queue +
background thread for the I/O itself). This is independent of, and stacks
with, the `@Async` MDC example above — one is about *your* code running off
the request thread, the other is about *logging I/O* running off it.

## Safe logging

Two things are deliberately kept out of the logs:

- **Credentials.** `LoggingController.SensitiveRequest` overrides `toString()`
  to print `SensitiveRequest[REDACTED]`, so logging the DTO by mistake can't
  leak `password` or `accessToken`. `SafeLoggingExamples` only ever logs a
  masked email (`***@example.com`).
- **Forged log lines.** `{}` placeholders alone do **not** stop user input
  from injecting `\r\n` (or the Unicode line/paragraph separators) to fake a
  new log entry — e.g. a fake `ERROR` line. `SafeLoggingExamples.oneLine(...)`
  replaces every control character (and the Unicode line/paragraph separators U+2028/U+2029) with `_` before
  logging, so injected content stays embedded inside the original field
  instead of becoming its own line. See `sample-output.txt`, section 10, for
  a real attempt against `/safe-text`.

## HTTP request logging

`RequestLoggingFilter` logs one `http.completed` event per request with
method, **matched route template** (not the raw path — so path segments like
an ID or a leaked secret never appear), status, and elapsed time. Query
strings are never logged at all.

## Deliberate simplifications

- **No log aggregation backend.** JSON/file profiles produce output meant for
  a real log pipeline (ELK, Loki, etc.), but none is wired up here — this
  project stops at "produce the right log line."
- **`X-Request-ID` validation is a simple allow-list regex**
  (`[A-Za-z0-9._-]{1,64}`), not a strict UUID check, so callers can supply
  their own trace ID format as long as it can't break the log line.
